# UI 质感重构 Spec

日期：2026-11-21

## 目标与方向

沿用远端陶土色与中文界面，建立「暖色底面、清晰内容、玻璃交互层」的视觉系统。首页首先帮助用户判断今天还要做什么，再提供回顾信息。保留现有 React / Tailwind / Motion / Supabase 架构与业务规则。

## 分期

1. **本次实现**：首页信息层级、普通/紧凑习惯卡片、三层材质、桌面双栏、已完成折叠、清晰的独立打卡入口。
2. 后续：全站导航和弹层交互深度统一（含抽屉拖拽）、更完整的打卡状态过渡。
3. 后续：统计、管理与个人页面的整体结构和图表规范收尾。

## 第一轮设计

- **背景层**：低对比暖灰米白，弱化彩色光斑和纹理，停止持续背景漂移。
- **内容层**：首页任务行与趋势面板使用接近实色的暖白表面、轻边框与浅阴影；普通内容不跟随指针发光。
- **交互层**：底部导航、菜单、弹层保留玻璃质感。输入框使用轻凹陷表面。
- **首页层级**：日期与标题 → 今日摘要（剩余/完成数量及进度）→ 待完成习惯 → 可折叠已完成习惯；组合为次级快捷区，趋势为回顾信息。
- **响应式**：手机单列，普通习惯为列表；紧凑模式为网格。大屏在内容区足够宽时使用主任务列与回顾辅列，辅列包含组合及七日趋势。
- **文字**：普通习惯名称 15–16px、允许两行；辅助信息 12–13px；数字使用等宽数字。沿用现有适合中文的系统字体。
- **操作**：习惯主体不提交打卡；独立打卡按钮与更多按钮均为原生 button，目标至少 44×44px，无嵌套交互元素。已完成项目允许明确地「再记一次」。备注、撤销、补卡、组合及搜索功能保持可用。
- **反馈**：按下即时反馈，请求中禁用同项重复提交；成功后显示完成状态，移动至完成分组。已完成分组默认展开，用户可收起；搜索时保持结果可见。
- **动效**：短促、克制，避免整屏重复弹跳和持续光效；遵循 reduced-motion / reduced-transparency / increased-contrast 偏好。

## 数据与状态

不改变数据库、权限、导入导出或统计算法。摘要仅按当前有效习惯计算完成数；加载与失败时不展示误导性的完成结论。保留加载、部分失败、空列表、无搜索结果、全部完成、长名称、多项目、请求失败重试等状态。

## 验收

- TypeScript、生产构建通过；ESLint 无新增错误。
- 390px 手机和 1280/1440px 桌面无控件重叠或内容横向溢出；320px 窄屏仍可操作。
- 搜索、只看未打卡、视图切换、已完成折叠、备注入口、追加打卡和撤销可用。
- 点击行主体不会提交；显式打卡按钮提交一次；请求期间再次点击不产生重复提交；失败后可重试。
- 采用隔离模拟数据验证 UI，不访问真实用户记录；截图明确为模拟数据。
- 不修改自动生成的路由树，不自动提交或推送。
